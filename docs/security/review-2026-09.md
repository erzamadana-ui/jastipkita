> Diperbarui 2026-10-04: SEC-15 FIXED, SEC-14 MITIGATED/ACCEPTED; angka Low juga dikoreksi untuk SEC-16/17/20 yang sudah FIXED 2026-09-28 (tabel sebelumnya masih 3/6).
> Diperbarui 2026-10-04 (A2): SEC-18 dan SEC-19 FIXED (keputusan CEO atas delegasi Commissioner); jeda rekening payout baru (sisa SEC-12) diterapkan.

Temuan paling serius (**SEC-01, High**): MFA admin hanya ditegakkan di UI. Gerbang TOTP saat login di Admin SPA adalah flag
`sessionStorage`; API menerima sesi admin hasil OTP saja untuk **semua** endpoint baca `/v1/admin/*`, aksi admin non-step-up, dan
streaming dokumen KYC. Siapa pun yang mendapat OTP seorang admin (phishing, SIM swap) memperoleh akses baca ke PII seluruh pengguna.
Sudah diperbaiki di server (sesi admin wajib terverifikasi MFA ≤ 12 jam; step-up ≤ 15 menit tetap untuk aksi sensitif).

Temuan uang yang diperbaiki: batas promo tidak divalidasi ulang saat checkout (**SEC-02**), webhook pembayaran bisa mengamankan dana
hanya dengan token callback walau penyedia menyatakan belum dibayar (**SEC-03**), klaim retry Idempotency-Key tidak atomik (**SEC-04**).

Yang **terverifikasi aman** (dengan test otomatis baru): tidak ada IDOR pada 65 kasus rute ber-path-id, semua 141 operasi admin
menegakkan permission least-privilege, tidak ada SQL injection, tidak ada kebocoran `*_enc`/hash/rekening di respons, race uang
(double checkout, replay webhook, refund vs konfirmasi) tidak bisa mengeluarkan dana melebihi escrow, hash chain audit tahan
terhadap insert jahat oleh `jk_app`.

Pembajakan tujuan refund pasca-ATO (**SEC-12**) dan jendela trust-on-first-use pendaftaran TOTP admin (**SEC-13**) sudah
diperbaiki pada putaran tindak lanjut QA (2026-09-28, migrasi 0090). Origin web yang berbagi domain dengan aplikasi lain (**SEC-14**)
**dimitigasi** 2026-10-04 (keputusan Commissioner: tetap di `/jastipkita`; CSP + refresh token di cookie HttpOnly SameSite=Strict + access
token di memori) dengan risiko sisa yang diterima: XSS di halaman lain origin yang sama masih dapat bertindak di peramban korban (lihat
SEC-14). Replay ID token OAuth (**SEC-15**) diperbaiki (nonce wajib per penyedia + sekali pakai). Ditambah gap lama di `docs/09-security.md` §3 (pemindai malware nyata, WAF, checkpoint WORM audit, pentest eksternal).

## 2. Metodologi

1. **Baca dokumen dulu**: `CONVENTIONS.md`, `docs/09-security.md`, checklist keamanan, `docs/10-privacy.md`, `docs/04-payments-ledger.md`,
   `docs/api/*.md` — setiap klaim kontrol diperlakukan sebagai hipotesis yang harus dibuktikan di kode.
2. **Tinjauan kode manual** berorientasi penyerang per lapisan: middleware (auth, rate limit, idempotency, request context), modul auth,
   setiap service dengan path id, alur uang (checkout → webhook → ledger → refund/payout), file upload, ekstraksi URL, admin, DB
   (grants, SECURITY DEFINER, anonymisasi), CI/CD, Dockerfile, wrangler, Admin SPA, web Astro, mobile Flutter.
3. **Grep sistematis**: `sql.unsafe`/konkatenasi SQL, `LIKE ${…}`, `SELECT *` yang dikembalikan ke klien, `innerHTML`/`set:html`,
   logger + PII, `pull_request_target`/ekspresi `${{ }}` di `run:`, `passthrough`/`c.req.json()`.
4. **Test yang gagal dulu**: setiap dugaan dibuktikan dengan test yang GAGAL pada kode lama lalu LULUS setelah perbaikan
   (dicek eksplisit untuk SEC-01, SEC-02, SEC-04 dengan me-revert perbaikan sementara). Race condition diuji dengan request paralel
   dan, bila perlu, lock baris dari sesi DB lain agar balapan deterministik.
5. **Test verifikasi luas** (bukan per-bug): matriks RBAC admin yang dienumerasi dari dokumen OpenAPI + penanda permission pada
   middleware, matriks IDOR pada graf objek nyata, sweep eksposur data seluruh endpoint GET admin, SSRF encoding, header keamanan.
6. `pnpm audit --prod` (hasil: **0 kerentanan diketahui**, 2026-09-28).

**Tidak dilakukan** (di luar kemampuan review kode): pentest black-box pada environment ter-deploy, uji Cloudflare/R2/Neon/Xendit nyata,
analisis biner mobile, fuzzing, uji beban DoS. Lihat §6.

## 6. Risiko sisa & rekomendasi sebelum launch

**Wajib sebelum production (gerbang):**
1. ~~Tutup SEC-12 / SEC-13~~ — **selesai 2026-09-28** (step-up OTP + review nama; enroll TOTP hanya dari sesi OTP segar, reset
   maker-checker). Tetap: onboarding admin dengan TOTP pada hari yang sama dengan grant; putuskan jeda 24 j untuk rekening refund baru
   (rekening **payout** baru sudah dijeda 24 j sejak 2026-10-04).
2. ~~SEC-14: subdomain khusus~~ — **keputusan 2026-10-04: tetap di `/jastipkita`**; mitigasi engineering selesai (CSP, refresh token di cookie HttpOnly SameSite=Strict, access token di memori). Tetap wajib: CSP setara di **seluruh** origin `antarkitaindonesia.com`, review keamanan halaman AntarKita lain, `frame-ancestors` via header host (DevOps + pemilik `antarkita-landing`).
3. **Pentest eksternal** (API, Admin SPA, mobile) oleh pihak ketiga, fokus logika bisnis uang (price change, cancellation matrix,
   dispute resolution) — review ini berbasis kode, bukan black-box.
4. **Cloudflare**: domain kustom + WAF managed rules + Rate Limiting rules (OTP request/verify, login OAuth, checkout, webhook per IP),
   Cloudflare Access (Zero Trust) di depan host Admin SPA; batasi origin Node (bila dipakai) hanya dari IP Cloudflare/Tunnel supaya
   `CF-Connecting-IP` tidak bisa dipalsukan.
5. Pemindai malware nyata (clamd) — production kini menolak boot tanpa itu (SEC-08).
6. Alert keamanan: `REFRESH_TOKEN_REUSE`, `MFA_FAILED` beruntun, `MFA_RECOVERY_CODE_USED`, `ADMIN_PII_REVEALED`, `MALWARE_UPLOAD`,
   `ALERT payment.webhook_not_confirmed_by_provider` (baru, SEC-03), `ALERT payment.amount_mismatch`, `OTP_RATE_LIMITED` (lonjakan).

**Prosedur rotasi kunci (tulis sebagai runbook, uji di staging):**
- `JWT_SECRET`: rotasi = semua access token (≤ 15 mnt) invalid; refresh token tetap → klien refresh otomatis. Dukung dua secret (verify-lama/
  sign-baru) bila ingin tanpa gangguan.
- `DATA_ENCRYPTION_KEYS`: tambah kunci baru di depan (aktif), biarkan lama untuk dekripsi, jalankan re-encrypt job, baru hapus kunci lama.
  Salinan escrow offline (Owner + DPO).
- `HMAC_PEPPER`: **tidak boleh** dirotasi setelah ada data (lookup/dedupe rusak) — hanya bila bocor, dengan migrasi re-hash terencana.
- `XENDIT_WEBHOOK_TOKEN`: rotasi di dashboard Xendit + secret Worker dalam satu jendela; SEC-03 membuat token bocor tidak lagi cukup untuk
  mengamankan dana, tetapi tetap rotasi segera.
- Token Cloudflare/Neon/Resend/Twilio/FCM: token berlingkup minimum, rotasi 90 hari & saat staf keluar.

**Program lanjutan:** bug bounty privat (setelah pentest), threat model per fitur (checkout, KYC, payout), pin SHA action pihak ketiga
(SEC-R5), wrangler sebagai devDependency terkunci, checkpoint audit WORM (SEC-R4), review ulang matriks peran admin (least privilege
`SUPER_ADMIN` sangat luas), sertifikat pinning mobile dievaluasi setelah beta.
